# Attest Tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. One commit per task.

**Goal:** Every request the SDK sends to `rocalytics-api` (except the attribution worker's `/install` ping) and every analytics batch it sends to the warehouse ingest carries `Authorization: Bearer <token>`, where the token comes from `rocalytics-api` `POST /attest` after Apple App Attest or Google Play Integrity proved the install genuine. An app without the native module, a device that can't attest, or a token that doesn't fit the request keeps working exactly as today, without the header.

**Architecture:** Three layers.
1. A pure token manager in `src/core/attest.ts`: cache tied to `app_id` + `platform` + `roca_id`, single flight, renewal in the last 2 hours, a wait cap, backoff, the iOS key lifecycle. It talks to an injected `AttestProvider` and `fetch`, so it is fully unit-tested with the existing fakes.
2. A separate Expo module package, `@rocapine/rocalytics-attest` (Swift + Kotlin + config plugin), in `native/attest/` of this repo. The SDK **never requires its JS package**: `src/client/native.ts` probes the native module `RocaAttest` through `requireOptionalNativeModule` (expo-modules-core, already a peer) and uses the object it returns. So the SDK gains no peer dependency, and an app that doesn't install the package still bundles.
3. Wiring: `RocalyticsClient` owns the manager and adds the header to its own requests; `createAnalytics` gets a `headers(batch)` option and the app passes `(batch) => client.attestHeaders(batch)`, which only returns a header when every event of the batch belongs to the token's roca_id. `/analytics` keeps not importing `/client`.

**Tech Stack:** TypeScript, vitest, Expo Modules API (Swift, Kotlin), `DCAppAttestService` (DeviceCheck), Play Integrity standard requests (`com.google.android.play:integrity`).

**Spec:** [proposal](https://claude.ai/code/artifact/f400e970-65e1-4f81-a44d-570cc04a1924) · [technical companion](https://claude.ai/artifact/SyFiEiocSCozCy2FUcC7YZ) (binding string, SDK state machine, native module surface, error tables). The server is built: `rocalytics-api` `supabase/functions/attest/` and `supabase/functions/track/attestation.ts` (Rocapine/rocalytics-api#121; its plan is `docs/rooms/2026-11-23-attest-plan.md`, its runbook `supabase/functions/attest/README.md`). Where this plan and the companion differ, the API as built wins: it is what the SDK talks to. Ingest: `rocalytics-warehouse` `docs/superpowers/plans/2026-11-23-attest-token-check.md`.

## Global Constraints

- **Gate for every task:** `npm run lint && npm run type:check && npm run type:check:tests && npm test`. Tasks that touch `src/**/index.ts` exports or `package.json` also run `npm run build && npm run check:exports`.
- **No new dependency of any kind** in the SDK's `package.json`: `test/deps.test.ts` ("declares no runtime, optional or bundled dependency"; "its only peers are the /client native modules") stays green unchanged. The attest module is reached only through `core.requireOptionalNativeModule("RocaAttest")`.
- `/core` and `/analytics` import only relative paths; `/analytics` never imports `/client` (`test/deps.test.ts`).
- **Binding string:** `` `${challenge}|${app_id}|${roca_id}` ``. The native module hashes it (SHA-256 of the UTF-8 bytes). Android sends `requestHash = base64url(SHA-256(binding))` without padding, 43 chars.
- **API contract (as built):**
  - `GET {base}/functions/v1/attest/challenge?app_id=<app_id>&platform=<ios|android>` → 200 `{ "challenge": "<43 base64url chars>", "expires_at": <unix seconds> }`; 400 `{ "error": "unknown_app" | "bad_request" }`.
  - `POST {base}/functions/v1/attest`, JSON body, one of:
    - `{ "kind": "ios_attestation", "app_id", "roca_id", "challenge", "key_id", "attestation", "app_version"? }`
    - `{ "kind": "ios_assertion", "app_id", "roca_id", "challenge", "key_id", "assertion", "app_version"? }`
    - `{ "kind": "android_integrity", "app_id", "roca_id", "challenge", "integrity_token", "app_version"? }`
  - `key_id`, `attestation`, `assertion`: base64 as the native APIs return them. `app_version`: string ≤ 32 chars (`nativeApplicationVersion`), omitted when null or longer. `app_id`, `roca_id` ≤ 128 chars.
  - → 200 `{ "token": "<JWT>", "expires_at": <unix seconds> }`; 400 `{ "error": "invalid_challenge" | "unknown_app" | "bad_request" }`; 401 `{ "error": "attestation_failed", "reason": "<reason>" }`; 409 `{ "error": "unknown_key" }` (iOS assertion only: unknown, revoked, or the roca_id changed); 503 `{ "error": "upstream_unavailable" }`; 500 `{ "error": "internal_error" }`.
  - Token payload claims: `iss`, `aud`, `app_id`, `platform` (`ios` | `android`), `roca_id`, `ikey`, `verdict`, `iat`, `exp` (`exp = iat + 86400`), `jti`.
- **The token must match the request:** `/track` and the ingest answer **403 `token_mismatch` even in log mode** when the token's `app_id`, `platform` or `roca_id` differs from the request's (`X-Application-ID`, `X-Platform`, `X-Roca-ID`; for the ingest, the batch's `app_id`, `platform` and every event's `roca_id`). The ingest's 403 body is `{"outcome": "rejected"}`, which the analytics tracker treats as final and drops the batch. So a header is sent only when it matches, and a cached token is never used for another roca_id.
- `roca_id` changes on an install through `RocalyticsClient.adoptRocaId` (W2A). The iOS keyId lives in `UserDefaults` (dies with a reinstall); the roca id and the token cache live in the secure store.
- **The SDK does not implement the API's `debug` kind:** a debug secret shipped in an app binary protects nothing. Simulators and emulators simply send no header.
- **Never throw, never block:** a request waits at most `attest.waitMs` (default 3000 ms) for a token on the first attestation, and not at all once a token is cached or the session is `unsupported` / `rejected`.

## Review Focus

1. **`adoptRocaId` mid-session.** The cached token belongs to the old roca_id: the next request must go out without it (or with a new one), never with the old one; the iOS renewal then gets 409 and re-attests (task 2, task 4).
2. **Analytics batches that mix roca_ids.** Events queued before `adoptRocaId` keep the old roca_id; a batch holding them must go out without the header, never with the new roca_id's token (task 4 `attestHeaders`, task 5).
3. **Device clock wrong by hours or days.** A token must not look expired the moment it arrives (renewal loop) nor stay "valid" forever. Expiry is measured on the device clock from the token's own lifetime (`exp − iat`) counted from the moment it was received (task 1 `readTokenLifetime`, task 2).
4. **Concurrent first requests on a cold start.** Identify, `install`, the onboarding and paywall sinks and an analytics flush all ask for a token at once: one challenge, one proof, one `POST /attest` (task 2).
5. **Repeated failures don't hammer anything.** 401 stops attestation for the session; `unknown_app` and unsupported devices stop it for the session; 5xx, 503, network errors and Play's transient errors back off 30 s → 2 min → 10 min; an invalidated iOS key is replaced once, not in a loop (task 2).

// src/core/attest.ts
export const bindingString = (challenge: string, appId: string, rocaId: string): string => `${challenge}|${appId}|${rocaId}`;

export type AttestPlatform = "ios" | "android";

/** What the native module gives the manager. Every function rejects with an Error whose `code` is `E_DC_<n>`, `E_PI_<NAME>` or `E_ATTEST_UNKNOWN`. */
export type AttestProvider =
  | {
      platform: "ios";
      isSupported(): Promise<boolean>;
      generateKey(): Promise<string>;                                   // keyId, base64
      attestKey(keyId: string, binding: string): Promise<string>;       // attestation object, base64
      generateAssertion(keyId: string, binding: string): Promise<string>; // assertion, base64
      getStoredKeyId(): Promise<string | null>;
      setStoredKeyId(keyId: string | null): Promise<void>;
    }
  | {
      platform: "android";
      isSupported(): Promise<boolean>;
      prepare(cloudProjectNumber: string): Promise<void>;
      requestToken(binding: string): Promise<string>;                   // integrity token (compact JWE)
    };

export type AttestState = "idle" | "fetching" | "valid" | "renewing" | "backoff" | "unsupported" | "rejected";

/** The token's lifetime in seconds (`exp − iat` from its payload, unverified), or null when it can't be read. */
export function readTokenLifetime(jwt: string): number | null;

export type AttestResponseAction =
  | { action: "token"; token: string }
  | { action: "new_challenge" }      // 400 invalid_challenge
  | { action: "new_key" }            // 409 unknown_key
  | { action: "unsupported"; detail: string }  // 400 unknown_app
  | { action: "rejected"; detail: string }     // 400 bad_request, 401, any other 4xx, a 200 without a token
  | { action: "backoff"; detail: string };     // 5xx (503, 500), 429, network error (status 0)
export function classifyAttestResponse(status: number, body: unknown): AttestResponseAction;

export type ProviderErrorAction = "unsupported" | "new_key" | "backoff" | "config" | "rejected";
export function classifyProviderError(error: unknown): ProviderErrorAction;
```

`classifyProviderError` by `error.code`:
- `unsupported`: `E_DC_1` (featureUnsupported), `E_PI_API_NOT_AVAILABLE`, `E_PI_PLAY_STORE_NOT_FOUND`, `E_PI_PLAY_SERVICES_NOT_FOUND`, `E_PI_PLAY_STORE_ACCOUNT_NOT_FOUND`, `E_PI_PLAY_SERVICES_VERSION_OUTDATED`, `E_PI_PLAY_STORE_VERSION_OUTDATED`.
- `new_key`: `E_DC_3` (invalidKey).
- `backoff`: `E_DC_0` (unknownSystemFailure), `E_DC_4` (serverUnavailable), `E_PI_NETWORK_ERROR`, `E_PI_GOOGLE_SERVER_UNAVAILABLE`, `E_PI_TOO_MANY_REQUESTS`, `E_PI_INTERNAL_ERROR`, `E_PI_INTEGRITY_TOKEN_PROVIDER_INVALID` (the module already retried once).
- `config`: `E_PI_CLOUD_PROJECT_NUMBER_IS_INVALID`, `E_DC_2` (invalidInput: our bug).
- `rejected`: anything else, including errors without a `code`.

Check the `DCError.Code` numbers against Apple's `DCError` documentation and the `StandardIntegrityErrorCode` names against Google's before writing the table; if a value differs, the documentation wins and the test follows it.

export interface AttestFetch {
  (url: string, init: { method: "GET" | "POST"; headers: Record<string, string>; body?: string }): Promise<{ status: number; json(): Promise<unknown> }>;
}

export interface AttestManagerOptions {
  provider: AttestProvider;
  appId: string;
  /** The current roca id, read on every getToken: a change (adoptRocaId) invalidates the cached token. */
  getRocaId(): string | null;
  /** `${baseUrl}/functions/v1/attest` */
  attestUrl: string;
  fetch: AttestFetch;
  storage: KeyValueStorage;
  clock: Clock;
  timers: Timers;
  appVersion?: string | null;
  cloudProjectNumber?: string;   // Android; without it Android is unsupported
  onDiagnostic?: DiagnosticHandler;
}

export interface AttestTokenManager {
  /** A token valid for the current app, platform and roca id, or null. Resolves within `waitMs` (default 3000). Never throws. */
  getToken(waitMs?: number): Promise<string | null>;
  state(): AttestState;
}

export const ATTEST_TOKEN_KEY = "rocalytics.attest.token.v1";
export const RENEW_BEFORE_MS = 2 * 3600_000;
export const BACKOFF_MS = [30_000, 120_000, 600_000] as const;

export function createAttestTokenManager(options: AttestManagerOptions): AttestTokenManager;
```

Stored record (JSON under `ATTEST_TOKEN_KEY`): `{ "v": 1, "token": string, "app_id": string, "platform": "ios" | "android", "roca_id": string, "local_expires_at": number }` where `local_expires_at = clock.now() at receipt + readTokenLifetime(token) * 1000`. A record that doesn't parse, has another `v`, or another `app_id` / `platform` / `roca_id` than now is ignored and overwritten on the next token. A token whose lifetime can't be read is treated as `expires_at` from the response minus now (seconds), and as 0 (no cache) if that is not positive.

The flight (one at a time; concurrent callers join it):
1. `GET {attestUrl}/challenge?app_id=&platform=` → challenge (non-200 → `classifyAttestResponse`).
2. Binding with the roca id read at flight start.
3. iOS: `keyId = await getStoredKeyId()`; none → `generateKey()`, `attestKey`, body `ios_attestation`, then `setStoredKeyId(keyId)` **only after a 200**; stored → `generateAssertion`, body `ios_assertion`. Android: `prepare(cloudProjectNumber)` once per manager, then `requestToken`, body `android_integrity`.
4. `POST {attestUrl}` with `Content-Type: application/json`; `app_version` only when it is a string ≤ 32 chars.
5. Act on `classifyAttestResponse` / `classifyProviderError`:
   - `token` → store the record, state `valid`, reset the backoff index.
   - `new_challenge` → one more flight with a new challenge (once per flight).
   - `new_key` → `setStoredKeyId(null)`, one more flight with a fresh key (once per flight).
   - `unsupported` / `config` → state `unsupported` for the manager's life; diagnostic `attest-unsupported` (`attest-config` for config).
   - `rejected` → state `rejected` for the manager's life; diagnostic `attest-rejected` with the reason.
   - `backoff` → state `backoff`; no new flight until `BACKOFF_MS[i]` has passed (i = 0, 1, 2, then stays at 2); the iOS keyId is kept.
6. `isSupported()` false, or Android without `cloudProjectNumber` → `unsupported` without any request.

`getToken(waitMs)`:
- `unsupported` / `rejected` → null at once.
- A cached record for the current app/platform/roca with more than `RENEW_BEFORE_MS` left → that token, no network.
- With less than `RENEW_BEFORE_MS` but more than 0 left → that token at once, and a renewal flight starts in the background (state `renewing`); a failed renewal keeps it until it expires.
- Otherwise → start or join the flight (unless in backoff) and resolve with its token, or null after `waitMs`, whichever comes first. A flight that lands after the wait still stores its token for the next call.
- `getRocaId()` null → null.

## Rollout (with the other plans)

1. `rocalytics-api` `/attest` (Rocapine/rocalytics-api#121) and the warehouse ingest are deployed, in log-only mode, before any SDK release that sends tokens.
2. **This SDK must not ship tokens before task 4's roca-id binding and task 5's per-batch check are in:** the API and the ingest reject a mismatched token with 403 even in log mode, and a rejected analytics batch is dropped.
3. Each app ships a build with `@rocapine/rocalytics-attest`, the config plugin and an `attest_apps` row on the API. Older builds keep sending without the header.
4. Watch the attested share per app and version (`attest_events`, `events.attested`, `raw_events.events.attested`) before any app is enforced; the API README's "Before the first app goes to enforce" checklist applies.

## Not in this plan

- The API's `debug` kind (see Global Constraints).
- Apple's fraud metric (receipt exchange) and anything server-side.
- A token for the attribution worker's `/install` ping: the worker has nothing to check it with.
