# Attest Tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every request the SDK sends to `rocalytics-api` and to the warehouse ingest carries `Authorization: Bearer <token>`, where the token comes from `rocalytics-api` `POST /attest` after Apple App Attest or Google Play Integrity proved the install genuine. An app without the native module, or a device that can't attest, keeps working exactly as today, without the header.

**Architecture:** Three layers.
1. A pure token manager in `src/core/attest.ts`: caching, single flight, renewal in the last 2 hours, timeouts, backoff, the iOS key lifecycle. It talks to an injected `AttestProvider` and `fetch`, so it is fully unit-tested.
2. The native module ships as a **separate Expo module package**, `@rocapine/rocalytics-attest` (Swift + Kotlin + config plugin), in `native/attest/` of this repo. The SDK loads it lazily and optionally through `requireOptionalNativeModule("RocaAttest")` in `src/client/native.ts`, the one file allowed to load packages. Keeping native code out of `@rocapine/rocalytics-sdk` keeps the SDK's "no runtime dependency, optional Expo peers" promise, and lets an app adopt attestation with a new build while older builds keep sending untokened events.
3. Wiring: `RocalyticsClient` creates the manager when the module is present and adds the header to its own requests; `createAnalytics` gets a `headers` option so the app passes the client's header to the ingest sink. `/analytics` keeps not importing `/client`.

**Tech Stack:** TypeScript, vitest, Expo Modules API (Swift, Kotlin), `DCAppAttestService` (DeviceCheck), Play Integrity standard requests (`com.google.android.play:integrity`).

**Design:** [proposal](https://claude.ai/code/artifact/f400e970-65e1-4f81-a44d-570cc04a1924) · [technical companion](https://claude.ai/artifact/SyFiEiocSCozCy2FUcC7YZ): binding string, SDK state machine, native module surface, error tables, API contracts. Server side: `rocalytics-api` `docs/rooms/2026-11-23-attest-plan.md`. Ingest: `rocalytics-warehouse` `docs/superpowers/plans/2026-11-23-attest-token-check.md`.

**Gate for every task:** `npm run lint && npm run type:check && npm run type:check:tests && npm test`. Tasks that touch exports also run `npm run build && npm run check:exports`.

```ts
export const bindingString = (challenge: string, appId: string, rocaId: string) => `${challenge}|${appId}|${rocaId}`;

/** What the native module gives the manager. Each function hashes `binding` itself (SHA-256). */
export type AttestProvider =
  | {
      platform: "ios";
      isSupported(): Promise<boolean>;
      generateKey(): Promise<string>;
      attestKey(keyId: string, binding: string): Promise<string>;
      generateAssertion(keyId: string, binding: string): Promise<string>;
    }
  | {
      platform: "android";
      isSupported(): Promise<boolean>;
      prepare(cloudProjectNumber: string): Promise<void>;
      requestToken(binding: string): Promise<string>;
    };

export interface AttestToken { jwt: string; exp: number } // exp in seconds since the epoch
export type AttestState = "empty" | "fetching" | "valid" | "renewing" | "backoff" | "unsupported" | "rejected";
```

### Task 2: Token manager

**Files:**
- Modify: `src/core/attest.ts`
- Test: `test/attest.manager.test.ts`

The manager follows the companion's state machine. Its options:

```ts
export interface AttestManagerOptions {
  provider: AttestProvider;
  appId: string;
  getRocaId(): Promise<string>;
  /** rocalytics-api base, e.g. https://rocalytics-api.rocapine.io/functions/v1/attest */
  attestUrl: string;
  fetch: (url: string, init: { method: string; headers: Record<string, string>; body?: string }) =>
    Promise<{ status: number; json(): Promise<unknown> }>;
  storage: KeyValueStorage;          // token cache; iOS keyId goes in the native side (UserDefaults)
  clock?: Clock;
  timers?: Timers;
  cloudProjectNumber?: string;       // Android
  onDiagnostic?: DiagnosticHandler;
}
export interface AttestTokenManager {
  /** Resolves within `waitMs` (default 3000): a token, or null. Never throws. */
  getToken(waitMs?: number): Promise<string | null>;
  state(): AttestState;
}
```

- [ ] **Step 1: Write the failing tests**, using the fakes style of `test/fakes.ts` (fake clock and timers, a scripted `fetch`, a scripted provider):
  1. cached token with more than 2 h left → returned, no fetch;
  2. no token → `GET {attestUrl}/challenge?app_id=…&platform=ios`, then `POST {attestUrl}` with `{ kind: "ios_attestation", app_id, roca_id, challenge, key_id, attestation }`; token cached with its `exp`;
  3. iOS with a stored keyId → `kind: "ios_assertion"` and `generateAssertion`, no `generateKey`;
  4. 409 `unknown_key` → keyId dropped, one retry with a new key, then a token;
  5. ten concurrent `getToken()` calls → one challenge request (single flight);
  6. less than 2 h left → the cached token is returned at once and a renewal starts in the background; a failed renewal keeps the old token until it expires;
  7. provider rejects with `E_DC_1` (featureUnsupported) or `E_PI_API_NOT_AVAILABLE` → state `unsupported`, `getToken()` returns null with no further calls this session;
  8. 401 `attestation_failed` → state `rejected`, null, no retry this session;
  9. network error, 5xx, `E_DC_4` (serverUnavailable) → `backoff` at 30 s, then 2 min, then 10 min; the iOS keyId is kept across these retries;
  10. a slow attest (provider never resolves) → `getToken(3000)` resolves null after 3 s, and resolves the token on a later call once it lands;
  11. Android → `prepare(cloudProjectNumber)` once, then `requestToken(binding)`, body `kind: "android_integrity"`, `integrity_token`.
- [ ] **Step 2: Run, expect failure.**
- [ ] **Step 3: Implement** `createAttestTokenManager`. Store the token as JSON under `rocalytics.attest.token.v1`. The iOS keyId is not stored here: the native module keeps it in `UserDefaults` (companion, "Where the iOS keyId lives"), exposed through two extra provider functions `getStoredKeyId()` and `setStoredKeyId(id | null)`. Add those to the iOS variant of `AttestProvider` in this task.
- [ ] **Step 4: Run, expect pass.**
- [ ] **Step 5: Commit** `feat(core): attest token manager`

## Rollout (with the other plans)
1. `rocalytics-api` `/attest` and the warehouse ingest are live in log-only mode first; the SDK can ship before or after, since a token is only sent once `/attest` answers.
2. Each app ships a build with `@rocapine/rocalytics-attest` and the config plugin. Older builds keep sending without the header.
3. Watch the attested share per app and app version (`attest_events`, `events.attested`, `raw_events.events.attested`) before any app is enforced.
